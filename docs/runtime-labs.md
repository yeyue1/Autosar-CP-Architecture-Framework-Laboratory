# 运行期实验室学习指南

通信、存储、OS 与 XCP 四个工作区共用一套 `VehicleSimulator`。Gateway、Powertrain、Chassis、Body 拥有各自的启动、UDS、NvM、XCP 和 CDD 状态；页面顶部的目标 ECU 选择器决定当前正在观察和操作哪一个实例。

所有倒计时都由页面中的共享虚拟时钟推进。暂停页面不会偷偷消耗 S3、NM、NvM 或任务时间，因此相同操作序列可以确定性回放。

断电、复位或把启动流程回放到早期步骤时，目标 ECU 的 UDS 会话、XCP/DAQ、NM、CDD、计数器和未提交写入会一起回到生命周期边界；已提交的 NvM 记录与活动固件分区会保留。Gateway 拥有本页的多核 OS 教学实例，因此只有 Gateway 复位会同步重置该 OS。

## 通信与网络管理

### NM 休眠与唤醒

1. 点击「全部 ECU 上电到 RUN」。
2. 进入「通信与网络管理」，点击「释放全部 ECU」。
3. 分段推进时间，观察 `REPEAT_MESSAGE → READY_SLEEP → PREPARE_BUS_SLEEP → BUS_SLEEP`。
4. 点击「触发唤醒」，观察网关 NM 如何传播到共享网络的节点。

教学时间参数位于 [`src/vehicle.mjs`](../src/vehicle.mjs) 的 `NM_TIMING`。其他节点的 NM 报文会刷新接收超时，所以“释放本地请求”并不等于立即休眠。

### 应用 PDU 与节点丢失

应用信号按 `AliveCounter / Actuator / Filtered / Sensor` 编成四个教学字节。关闭 Body ECU 后推进超过 600 ms，其他相关节点会报告周期报文超时 DTC；即使 Body 从监督开始后从未发出第一帧，期望节点监督仍会超时。恢复 Body 后状态字节更新为恢复状态，并进入 NvM 保存队列。

### ISO-TP 与 CAN FD

在逐帧传输台选择 24 或 100 字节负载，对比 Classic CAN 与 CAN FD。调整 Block Size 和 STmin，再分别注入丢 FC、丢 CF 或错误序号。CAN FD 主要减少承载相同负载所需的数据帧，不能替代 ISO-TP 的流控、顺序检查和超时。

## 存储实验室

一次写入依次经过：

```text
NvM → MemIf → Fee → Fls → verify → commit
```

推荐实验：

1. 写入一个新 Gain，只推进 20 ms 后断电，再上电观察旧值恢复。
2. 再写一次并推进 100 ms，确认提交后的新值可以恢复。
3. 打开“下一次写入 CRC 故障”，确认坏记录不会覆盖上一条有效记录。
4. 开启写保护，确认请求被拒绝且存储内容不变。
5. 排队多次写入触发 GC，观察有效记录先复制到备用扇区，再切换活动扇区。

Dem DTC 和 XCP 标定使用按块合并的持久化意图：若 NvM 因队列已满而暂时拒绝，界面不会把它误报成“已排队”，而会在 ECU 仍上电时节流重试，直到记录耐久提交。立即断电仍会丢弃尚未提交的请求，这正是本实验要展示的边界。

## OS 与多核调度

时间线使用 1 ms 粒度展示每个核当时运行的任务或 ISR。周期任务固定分配到不同核心，高优先级诊断任务可以抢占 Core 0 的后台任务。

- Cat1 ISR 不调用 OS 服务。
- Cat2 ISR 返回时通过 `SetEvent` 唤醒扩展任务。
- IOC 消息进入有界队列，在接收端通信任务运行时投递。
- Spinlock 实验让 control 与 comm 竞争共享资源。
- 将末核切为离线可观察等待任务、截止时间和启动屏障状态。

这是调度语义教学器，不实现真实 AUTOSAR OS API、栈、保护域或硬件中断控制器。

## XCP 在线标定

1. 保证目标 ECU 和网关在线，点击「连接 XCP」。
2. 开启 DAQ，推进时间，观察 10 ms 测量样本。
3. 修改 Gain、Filter 或 Threshold 并应用到 RAM，观察控制响应曲线变化。
4. 不保存就复位，参数会回到上次 NvM 已提交值。
5. 再次标定，点击「保存标定到 NvM」，到存储实验室等待队列提交后复位，确认新值恢复。

本实验只模拟连接、DAQ、标定页与持久化关系，不解析 ASAM XCP 报文或 A2L 文件。

## 跨工作区串联练习

建议完成一次完整因果链：

```text
关闭一个远端 ECU
  → 共享 CAN 上不再出现其应用 PDU
  → 观察节点检测周期报文超时
  → Dem 产生 DTC
  → NvM 异步保存 DTC
  → UDS 19 02 FF 读取该记录
  → 恢复 ECU 后观察 DTC 状态更新
```

这条路径能同时练习“通信故障”“诊断可见性”和“掉电持久化”三个不同层次，避免把它们误认为同一个模块的职责。
